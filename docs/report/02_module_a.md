# 보고서 초안: 4장 모듈 A, 읽기 시점 SECDED 교정

> 초안 (2026-11-13).
> - 숫자의 출처는 `docs/rq3_fused_results.md`, `docs/rq3_decode_inject_results.md`, 서버 결과 폴더(`results/rq2/`)다.
> - 4.4의 "재측정" 칸은 체크워드 오류 집계와 깊은 노드 선택을 고친 뒤 채운다.

## 4.1 목표

RQ1에서 확인한 것은 세 가지다.
- 단일 비트 오류는 16개 비트 위치 모두에서 출력을 바꾼다.
- K와 V는 민감도 차이가 없다.
- 오염된 값을 한 번이라도 읽으면 그 아래 자손 노드까지 오염이 번진다.

따라서 모듈 A의 목표는 다음과 같다.
1. 공유 KV를 **읽는 모든 경로**에서 1비트 오류를 고친다. 경로는 prefill(extend)과 decode 두 가지다.
2. 2비트 오류는 탐지해서 모듈 C로 넘긴다.
3. TPOT 증가를 3% 안팎으로 유지한다.

## 4.2 설계

### 코드

토큰 하나, KV 헤드 하나의 벡터(bf16 128개, 2048비트)마다 16비트 체크워드 하나를 둔다.
- 구성: 전체 패리티 P 1비트, 원소 라벨 신드롬 S_e 8비트, 원소 안 비트 신드롬 S_b 5비트, 검사용 Q 1비트.
- 원소 라벨과 비트 라벨은 0을 뺀 비밀 순열이다. 같은 비트 위치의 오류가 서로 상쇄되지 않게 한다.
- 계산은 싸게 할 수 있다. P와 S_b는 벡터의 모든 원소를 XOR한 값 하나에서 나오고, 원소별 패리티가 필요한 것은 S_e뿐이다.
- 코드워드 전체 기준으로 단일 오류 전수 교정, 이중 오류 전수 탐지를 참조 구현에서 검증했다(`docs/secded_verification.md`).
- 메모리: 체크워드 버퍼는 200 MiB로 KV 대비 0.78%다. KV 풀 크기(180,040토큰)는 그대로다.

### 저장

`set_kv_buffer`가 K와 V를 쓴 직후 인코딩 커널이 체크워드를 만든다. TPOT 비용은 +0.2~0.6%다. 저장 커널과 합치는 것은 비용 차이가 작아 하지 않았다.

### 읽기 1: extend(prefill) 경로

extend attention이 캐시된 prefix를 읽기 직전에, 그 레이어의 prefix 슬롯 전체를 검사하고 1비트 오류를 **메모리에서 제자리 교정**한다.
- prefix는 prefill마다 한 번만 읽히므로 따로 검사하는 비용이 작다(TPOT +0.3%p 이하).
- 고친 값이 메모리에 남으므로 이후 decode와 자손 노드의 prefill은 깨끗한 값을 읽는다. 파생 오염의 출발점을 막는 부분이다.

### 읽기 2: decode 경로

SGLang의 grouped decode attention 커널(stage 1)을 복사해 검사를 넣었다. 처음 만든 full 모드는 타일마다 신드롬 전체를 계산했다. 이 방식은 TPOT을 7~57% 늘려 경량 모드 네 가지를 시험했다.

| 모드 | 방식 | 생성 중 1비트 주입 결과 | TPOT (공유 프롬프트 동시 1/8/32) |
|---|---|---|---|
| full | 타일마다 전체 신드롬 | 출력 변화 0 | +7.5 / +19.1 / +57.2% |
| gate | P와 S_b로 먼저 거르고, 어긋난 벡터만 S_e 계산 | 0/120 | +4.0 / +7.2 / +26.1% |
| 샘플링 (s4, s16) | 타일을 4 또는 16스텝에 한 번 검사 | **비트 14에서 18~25/30 변화** | +1.6~1.0 / +3.4~1.9 / +11.0~8.0% |
| **sig + 되쓰기** | split 전체 XOR 서명 하나만 비교, 어긋나면 그 split만 full로 다시 계산하고 고친 값을 메모리에 되씀 | **0/120** | **+2.6 / +4.8 / +17.3%** |

- 샘플링은 검사를 건너뛰는 스텝에서 오염값을 그대로 읽는다. 비트 14는 한 스텝만 읽혀도 토큰이 바뀌어 교정 보장을 줄 수 없다. 그래서 제외했다.
- 되쓰기가 없으면 같은 오류를 스텝마다 다시 고쳤다(시행당 약 40회). 되쓰기를 넣은 뒤에는 시행당 1회다. 오류가 없을 때 비용 차이는 반복 편차 수준이다(−1.3~+1.6%p).
- **기본 모드는 sig + 되쓰기로 정했다.** 교정이 확인된 모드 중 가장 가볍다.

### 오류 집계

카운터 9개를 둔다. decode와 extend 각각의 K/V 교정 수와 교정 불가 수, 그리고 sig 재계산 split 수다. 2비트 탐지 위치를 모듈 C로 넘기는 오류 로그는 8주차에 넣는다.

## 4.3 검증 방법

결함 주입기로 공유 프롬프트 노드(864토큰)의 K 또는 V에 비트를 뒤집고, 후속 요청 4개의 출력을 golden과 토큰 단위로 비교한다(3.2절과 같은 방법). 주입 시점은 두 가지다.
- **hit 전:** 후속 요청이 prefix를 재사용하기 전에 주입한다. extend 경로를 시험한다.
- **생성 중:** 후속 요청이 4토큰을 생성한 뒤 주입한다. decode 경로를 시험한다. 해시 기준선이 놓치는 TOCTOU 조건이기도 하다.

결함이 없을 때는 보호를 켜도 출력이 비트 단위로 같았다(golden `94c11b0adbc5`).

## 4.4 결과

### RQ2(A): 교정과 탐지 (sig + 되쓰기)

|---|---|---|---|

| 단일 비트, hit 전, 나머지 위치 | 96 | 0/96 (0–3.8%) | 96회 모두 교정 |
| 단일 비트, 생성 중 | 96 | 0/96 (0–3.8%) | 96회 모두 교정 (sig 재계산 경유) |
| 같은 비트 위치 2비트, 생성 중 (비트 14, 7, 0 × K/V × 20) | 120 | 82/120 | 탐지 120/120 |
| 다른 비트 위치 2비트, 생성 중 (14·7, 14·0, 7·0 × K/V × 20) | 120 | 106/120 | 탐지 120/120 |
| 체크워드 비트 오류, K/V × 16비트 × 3 | 96 | 0/96 (0–3.8%) | 데이터 교정 0 (데이터 보존). 체크워드 오류 집계·되쓰기는 재측정 |
| 깊은 노드(자식 질문 노드) 단일 비트 | 재측정 | 재측정 | 1차 측정은 읽히지 않는 노드를 골라 무효 |

- 단일 비트는 비트 위치, K/V, 토큰 위치, 주입 시점을 가리지 않고 모두 교정되었다.
- sig 모드는 2비트를 같은 위치·다른 위치 합쳐 240회 모두 탐지했다. 설계상 놓칠 수 있다고 보았던 같은 위치 2비트도 포함이다. full 모드는 238/240이었다.
  - 예외 2회는 교정 불가가 아니라 1비트 교정 2회로 집계되었고 출력은 바뀌지 않았다.
  - 두 반전이 서로 다른 decode 스텝 사이에 하나씩 보인 것으로 추정한다. 확인은 남았다.
- 체크워드 비트가 뒤집혀도 데이터를 잘못 고친 경우는 없었다. 다만 1차 구현은 체크워드 오류를 세지도, 고쳐 쓰지도 않아 오류가 남아 있는 동안 sig 재계산이 스텝마다 일어났다(시행당 약 80회). 체크워드를 다시 계산해 써 넣고 카운터를 두도록 고쳤다.
- 2비트 시행에서 출력이 바뀐 것(같은 위치 82/120, 다른 위치 106/120)은 예상한 결과다. 탐지 뒤 재계산(모듈 C)이 아직 없기 때문이다. 비트별로는 14번 40/40, 7번 28/40, 0번 14/40이었다.

### RQ3(A): 오버헤드

TPOT 증가율은 보호 없음 대비이고 3회 반복의 중앙값이다.

| 워크로드 | 보호 없음 TPOT | 저장 시 인코딩만 | sig + 되쓰기 (전체) |
|---|---|---|---|
| 공유 프롬프트, 동시 1 | 24.13 ms | +0.5% | +2.6% |
| 공유 프롬프트, 동시 8 | 27.89 ms | +0.5% | +4.8% |
| 공유 프롬프트, 동시 32 | 40.98 ms | +0.2% | +17.3% |
| 무작위, 동시 8 | 28.89 ms | +0.6% | +2.8% |
| 무작위, 동시 32 | 49.34 ms | +0.6% | +2.5% |

- 메모리는 +200 MiB(KV 대비 0.78%)다.
- 문맥이 짧거나 공유가 적은 경우는 3% 목표 안에 든다.
- 긴 공유 프롬프트를 많은 요청이 동시에 읽으면(동시 32) +17%다. decode 검사 비용이 읽는 KV 양에 비례하기 때문이다. 8주차 과제로 남긴다.
- TTFT는 구성과 무관한 변동이 커서(보호 없음 기준값 자체가 63~76 ms로 흔들림) 최종 측정에서 반복 수를 늘려 다시 잰다.

## 4.5 한계

- sig 모드는 split 안에서 서명이 상쇄되는 짝수 개 오류를 놓칠 수 있다. 같은 위치 2비트 120회에서는 놓친 경우가 없었다. 2비트 탐지를 보장해야 하면 full 모드를 쓴다(비용이 더 큼).
- 3비트 이상은 오교정될 수 있다. 비밀 라벨로 확률을 낮추지만(E=8에서 약 27%, E=9에서 약 14%, 시뮬레이션) 막지는 못한다.
- 오래 읽히지 않는 슬롯에서 두 번째 비트가 쌓이는 것을 막는 백그라운드 scrub은 넣지 않았다. 읽히는 순간 고치므로 출력에는 영향이 없지만, 그 사이 2비트가 되면 모듈 C의 재계산으로 넘어간다.
- 하드웨어 ECC와의 실측 비교는 하지 않았다. 서버 GPU의 ECC가 꺼져 있고 일반 계정으로는 켤 수 없다. SECDED(72,64)의 이론값(메모리 6.25%, 대역폭 최대 12%)과 비교한다.
- page size 1, GQA decode 경로만 다룬다. MHA decode와 page size > 1은 범위 밖이다.
