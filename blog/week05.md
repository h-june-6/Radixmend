# [RadixMend 5주차·선행] 위협 모델에 숫자를 붙이고, 비교 실험 절차를 정하다

> 5주차 계획은 RQ1 결과를 받아 설계와 위협 모델을 확정하는 것이다. RQ1은 GPU 실험이라 아직이지만, SECDED 코드 자체의 한계는 계산으로 확정할 수 있다. 비교 실험 절차서도 미리 초안을 썼다.

## 1. "비밀 라벨로 확률적 완화"를 숫자로

기술서에는 3비트 이상 오류를 "비밀 라벨로 확률적으로 완화한다"고만 적었다. 2주차에 삼중 오류 15억 개를 전부 세어 봤기 때문에 이제 숫자를 적을 수 있다.

| 구성 | 체크워드 | 무작위 3비트 오류의 조용한 오교정률 |
|---|---|---|
| 순차 라벨 | 15비트 | 75.5% |
| 비밀 라벨, E=8, B=5 (기술서 설계) | 15비트 | 27.1% |
| 비밀 라벨, **E=9**, B=5 | 16비트 | **14.1%** |
| 비밀 라벨, E=8, B=6 | 16비트 | 17.1% |

4비트(짝수 개) 오류는 전체 패리티 Q가 0이라 99.99%가 탐지된다.

## 2. 설계 변경 제안: 16번째 비트를 원소 라벨에

체크워드는 int16으로 저장하므로 15비트 설계에서는 1비트가 놀고 있다. 이 비트를 원소 라벨 공간에 쓰면(E=8 → 9) 255개 중 128개를 쓰던 것이 511개 중 128개가 된다. 삼중 오류 신드롬이 빈 라벨에 떨어질 확률이 커져서 오교정률이 반으로 준다. 메모리 비용은 그대로 0.78%다. 비트 라벨 쪽을 넓히는 것(B=6, 17.1%)보다 효과가 크다.

그래서 기본값을 E=9로 바꾸자고 제안한다. 코드는 이미 `VecCode(e_bits_override=9)`로 지원하고, 이 구성도 단일 교정·이중 탐지를 전수 검증했다.

위협 모델 문서에는 이렇게 적을 생각이다. "벡터당 2비트 이하에서는 교정·탐지가 보장된다. 3비트는 라벨을 모르는 공격자 기준으로 약 14%가 조용히 오교정되고, 4비트는 거의 전부 탐지된다. 라벨을 아는 공격자는 3비트로 원하는 오교정을 만들 수 있다."

## 3. 코드 분석에서 나온 설계 변경점

1주차 SGLang 분석 결과 중 설계에 반영할 것들이다.

- **seq_lens는 ECC 대신 CPU 미러와 대조한다.** GPU `seq_lens`는 `+1`, `cumsum` 등 산술 소비자가 많아 상위 비트 ECC를 넣으면 고칠 곳이 너무 많다. SGLang이 이미 `seq_lens_cpu`를 유지하므로 choke point에서 비교하고, 다르면 CPU 값으로 덮어쓴다.
- **트리 삽입 순서.** overlap scheduler에서는 chunked prefill 결과가 오류 플래그 처리보다 먼저 트리에 들어간다. 모듈 C는 이 stash 시점을 플래그 처리 뒤로 옮겨야 한다.
- **오류 플래그 전달 경로.** 다음 스텝의 입력 토큰은 CPU가 아니라 GPU의 `FutureMap` 버퍼에서 읽는다. 샘플된 토큰을 폐기하려면 이 버퍼도 무효화해야 한다.
- **free list 격리 시 불변식 검사.** SGLang의 메모리 누수 검사는 available + evictable + protected = total을 확인한다. 격리한 slot 수를 이 식에 넣어야 한다.

## 4. 비교 실험 절차 (초안)

### hit 시점 해시를 SGLang에 이식

- 노드가 트리에 들어갈 때 KV 바이트의 digest를 계산해 노드에 저장하고, prefix hit 때 다시 계산해 비교한다. 다르면 그 노드부터 아래를 버리고 재계산한다.
- SGLang 기존 `hash_value`는 토큰 id의 해시라 KV 내용을 보지 않는다. 새 필드가 필요하다.
- GPU에는 SHA-256 커널이 없다. 그래서 두 버전을 만든다. 하나는 CPU `hashlib` SHA-256으로, 선행 연구와 같지만 느리다. 다른 하나는 SGLang에 이미 있는 GPU Adler-32를 재사용하는 버전으로, 빠르다.
- 이 이식으로 보일 것: hit 시점 검증과 실제 사용 사이의 시간 창에서 생기는 파생 오염은 막지 못한다.

### 하드웨어 ECC

- A6000에서 `nvidia-smi -e 1` 후 재부팅해서 켠다. 서버 관리자 권한이 필요하다.
- 같은 워크로드로 가용 메모리(6.25% 감소 예상), 처리량, TPOT을 비교한다.
- 소프트웨어 주입은 ECC가 지키는 DRAM 경로를 거치지 않는다. 그래서 ECC의 교정 능력은 실측이 아니라 SECDED(72,64)의 이론값으로 비교하고, 이 한계를 보고서에 적는다.

### 통계

비율에는 Wilson 95% 신뢰구간을 붙인다. 비트당 150회(선행 연구와 같은 수)면 50% 근처에서 ±8%p다. K 대 V처럼 두 조건의 차이는 Fisher exact test로 본다.
